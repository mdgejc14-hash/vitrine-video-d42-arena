## Chaîne serveur ↔ Android

- **F42 — P0 — Bootstrap profil jamais appelé (OUVERT)** : toutes les routes `/api/v1/me/*`, `/quota/consume`, `/audio/*` exigent `requireUser` = ligne `users` créée par `POST /api/v1/me/bootstrap` (src/index.js:5498). Android n'appelle JAMAIS bootstrap (inventaire des endpoints côté app : me/entitlements, me/referral/claim, me/welcome-grant, quota/consume, telemetry, audio/*). Conséquence compte réel Google : welcome-grant 404, quota 404, referral 404, entitlements 404, BGM audio 404 → autorité serveur morte en pratique, credits serveur jamais attribués/consommés. Preuve : grep endpoints + lecture dispatcher. Fix déterminé : `BackendSync.bootstrap()` POST après obtention du token (AuthActivity/Onboarding), idempotent serveur (ON CONFLICT firebase_uid).
- **F41 — P2 — Ordre claim/grant inversé (OUVERT)** : OnboardingActivity.persistGrantAndClaim demande le welcome-grant AVANT le claim referral ; serveur `routeWelcomeGrant` octroie 5 credits si `referrals.referred_id` existe déjà, sinon 3. - **F27 — P2 — Claim referral perdu si hors-ligne (OUVERT)** : échec claim = aucun rejeu (pas de file). Fix : pending claim en prefs `vv_sync` + rejeu dans flushPending.
- **F30 — P2 — Welcome-grant jamais redemandé (OUVERT)** : si requestGrant échoue à l'onboarding (offline), rien ne le rejoue ; flushPending ne couvre que quota/telemetry/entitlements. - **F14 — P1 — Double-tap Exporter = double débit local, 2e export jeté (OUVERT)** : ExportActivity.gateThen débite (atomicDebit + journal RESERVED) à CHAQUE tap ; enqueueUniqueWork(KEEP) jette le 2e work → RESERVED orphelin jamais CONFIRMED/COMPENSATED = credit perdu. Aussi : process kill entre débit et enqueue = orphelin. Fix : garde anti-réentrance + disable bouton + compensation des RESERVED orphelins non enqueued au démarrage.
- **F-INPUT — P3 — enqueueNow return silencieux après débit** si extra "input" absent → credit débité, rien ne se passe. Fix : compenser avant return.
- **F-quota-fp — P2/P3 — quota/consume : fingerprint non vérifié (OUVERT)** : `routeQuotaConsume` incrémente `welcome_grants.credits_used` pour N'IMPORTE QUEL fingerprint fourni (griefing possible du solde d'un tiers si fingerprint deviné ; secret = seule défense). - **F-webhook-plan — P3 — webhook billing : plan non validé** : e.plan hors grille accepté (subscription plan inconnu → pas d'élévation, mais données sales). Fix : exiger plan ∈ PLAN_GRID (400 sinon). Additif, ne casse aucun adaptateur légitime (la grille est le contrat 9.1).
- **F10 — P1 — Checkout CinetPay : URL inventée (OUVERT)** : `BillingCheckout.cinetPaySandboxUrl` → `https://sandbox-checkout.cinetpay.com/payment?...` = NXDOMAIN (prouvé DoH Cloudflare Status 3 ; api.cinetpay.com résout ✓). API réelle : `POST https://api-checkout.cinetpay.com/v2/payment` (JSON, apikey+site_id → payment_url) puis redirection ; vérif statut via `/v2/payment/check`. De plus CinetPay notifie son propre webhook (format différent de `/internal/billing/webhook` HMAC maison) → aucun adaptateur serveur. L'architecture n'est PAS « prête à recevoir les clés » : il manque (1) route serveur checkout (secret apikey côté worker), (2) adaptateur notify CinetPay→contrat interne, (3) client : appeler la route serveur puis ouvrir payment_url.
